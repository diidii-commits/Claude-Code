## 프로젝트 목적 (마케팅 컨텍스트)

- 던전앤파이터 유저 커뮤니티(아라드 게시판, 디시 던파갤 등)에 시딩할 **비공식 팬 콘텐츠**.

## 코드 구조 (index.html 내부)

모두 하나의 IIFE `<script>` 안에 있음. 섹션별 위치:

| 블록 | 내용 |
|---|---|
| 시드/PRNG | `hash32`(FNV-1a) + `mulberry32`. 시드 = `모험단명 + "\|" + KST날짜 + "\|arad"` |
| `TIERS` | 등급 5종(레어~태초) — 이름, 색상, 확률 `p`, 한 줄 코멘트. **확률 합계 = 1.00 유지** |
| 콘텐츠 풀 | `AMP`/`REINF`/`LOCK`(별점 1~5 코멘트, 배열 인덱스 = 별점-1), `CH_FLAVOR`, `TIMES`, `CLASSES`, `ITEMS`, `TABOO`, `QUOTES`, `PARTY_COMMENT`(% 구간별) |
| 생성 로직 | `makeFortune()` — 등급 먼저 롤 → `starsFor()`가 등급 인덱스로 별점에 +0.4/등급 가중(등급과 세부 운세가 따로 놀지 않게) |
| 렌더 | `render()` — innerHTML 조립. 사용자 입력(모험단명)은 `esc()`로 이스케이프 (XSS 방지, 유지할 것) |
| 복사 포맷 | `copyText()` — 게시판용 이모지 텍스트. 마지막 줄 URL은 `location.origin+pathname` 자동 |
| 공유 | `shareLink()` — `?adv=이름` 파라미터. 로드 시 파라미터 있으면 자동 감정 |

CSS: 다크 단일 테마(게임 세계관에 맞춘 의도적 선택). 등급색은 CSS 변수 `--tier`로 카드에 주입.
태초 전용 연출은 `.card.taecho`(프리즘 그라디언트 보더 + 글로우 펄스). `prefers-reduced-motion` 대응 있음.

## 튜닝 가이드 (자주 만질 값)

- **태초 확률**: `TIERS`의 `p: 0.03`. 바꾸면 UI 문구 2곳도 동기화(`nudge`의 "확률은 단 3%"와 og:title의 "3%").
- **지역 채널**: `REGIONS` 배열 `[지역명, 채널수]`. 채널은 `1 + Math.floor(rng()*region[1])`로 지역별 최대 채널 내에서 뽑힘. 서버 개편 시 이 배열만 수정.
- **파티 운(구 막공운)**: `PARTY_COMMENT`의 `[상한, 코멘트]` 구간. 라벨은 "오늘의 파티 운".
- **미니 운세**: `NPCS`/`ITEMS`/`ACTIONS`(각 `[값, 한 줄]`). 직업(각성명) 풀은 제거됨(구버전 명칭 리스크 회피).
- **콘텐츠 추가**: 풀 배열에 항목만 추가하면 됨. 단 `AMP`/`REINF`/`LOCK`은 정확히 5개(별점 매핑) 유지.
- **날짜 리셋 기준**: `kstDateKey()`가 Asia/Seoul 고정. 유저 로컬 시간 아님(의도된 동작).
- **폰트**: 헤드라인 DNFForgedBlade, 본문 SUIT. `@font-face`가 넥슨 CDN 직링크(CORS 허용). 오프라인 단일파일이 필요해지면 base64 임베드로 전환.
- **감정 연출**: `playAndReveal()`이 항아리 흔들림→버스트→카드 순서. 타이밍은 640ms/1360ms setTimeout. `particleBurst()`는 `try/catch`라 실패해도 결과는 나옴.

## 다음 개발 백로그 (우선순위 제안)

1. **배포** — GitHub Pages 또는 Cloudflare Pages. 파일 하나라 바로 됨. 배포 후 og:url 추가.
2. **OG 썸네일 이미지** — 커뮤니티/카톡 링크 미리보기가 바이럴의 절반. 1200×630 정적 이미지 제작 후 `og:image` 연결. (현재 텍스트 OG만 있음)
3. **결과 카드 이미지 저장** — Canvas로 카드를 PNG로 그려 "이미지로 저장" 버튼 추가. 스크린샷보다 인증 마찰이 더 줄어듦. 외부 라이브러리(html2canvas) 없이 직접 그리는 걸 권장(현재 무의존성 유지).
4. **카카오톡 공유** — Kakao JS SDK는 앱 키 필요 + 도메인 등록 필요. 배포 후 검토.
5. **시즌 콘텐츠 로테이션** — 콘텐츠 풀을 월별/이벤트별로 갈아끼우는 구조(예: `POOLS[월]`). 재방문 신선도 유지.
6. **가벼운 조회 카운터** — "오늘 N명이 감정받음" 사회적 증거. 단, 서버/외부 API가 필요해지므로 개인정보 미수집 원칙과 충돌하지 않게 익명 카운트만.

## 주의사항 (지킬 것)

- **면책 고지 유지**: 푸터의 "비공식 팬 콘텐츠 / 네오플·넥슨과 무관 / 실제 확률과 무관" 문구는 어떤 리뉴얼에서도 삭제 금지. IP 리스크 + 커뮤니티 반감("확률 낚시") 방어선.
- **개인정보 무수집 유지**: 입력값 저장·전송 없음을 광고하고 있음. 트래킹 스크립트를 붙이는 순간 커뮤니티에서 역바이럴 리스크. 붙여야 한다면 쿠키리스 익명 집계만.
- **공식 에셋 사용 금지**: 게임 아트/로고/BGM 등 공식 리소스를 넣지 말 것. 현재는 텍스트+CSS만이라 안전.
- **직업명(`CLASSES`) 검수**: 각성명 목록은 기억 기반이라 오탈자나 구버전 명칭이 있을 수 있음. 커뮤니티는 이런 디테일에 민감하므로 현행 명칭으로 검수 권장. `TIMES`·플레이버 텍스트의 시간대 드립도 실제 던전 운영 방식과 크게 어긋나지 않는지 확인.
- **결정론 유지**: "하루 동안 같은 결과"가 콘텐츠의 신뢰 장치. `Date.now()`·`Math.random()` 기반 로직을 섞지 말 것. 신규 랜덤 요소는 반드시 기존 `rng()`에서 뽑되, **기존 `rng()` 호출 순서 뒤에 추가**해야 같은 날 결과가 바뀌지 않음.

## 검증 방법

- 같은 이름 반복 입력 → 동일 결과 확인 (결정론)
- `?adv=이름` URL 직접 진입 → 자동 감정 + 동일 결과 확인
- 태초 연출 확인: `TIERS`에서 태초 `p`를 임시로 1.0 근처로 올려 확인 후 원복
- 모바일 뷰포트(375px)에서 카드 레이아웃·복사 버튼 확인 (유입 대부분 모바일 가정)
